# 周四交流 · A4 现场速查表

> 打印一页带走。完整材料见 `docs/ENTERPRISE_MENTOR_BRIEFING.md`。

## 一、去的目标（只有三个）

1. 让老师看懂我们**做了什么**（30%）
2. 听老师讲**酒店真实怎么干活**（40%）
3. 争取**一个低成本验证机会**（30%）——不是当场谈采购

## 二、13 分钟流程（手机设好计时）

| 时间 | 动作 | 关键句 |
|---|---|---|
| 0–2 | 找酒店 → 选一家真实收录酒店 | 收录 19 家，星级来自来源标注，没标注就写未标注 |
| 2–5 | 城市活动地图 + 活动清单 | 436 条记录 / 416 个身份；太仓直接归属 16 条，不说成覆盖充分 |
| 5–7 | 工作台：关注 → 待跟进 | 这几个状态是给员工用的，店长能看到谁在跟进 |
| 7–9 | 图谱：用问题查图谱 | 关系有来源，缺的写待补充，我们不补关系 |
| 9–11 | 商圈洞察 + 数据质量 | 情景是参数算的，缺参数不出数；每条来源可点开 |
| 11–13 | 登录 → 导出城市简报 | 可直接进周会，每行都有来源 |

## 三、必须主动说的三句

- 「我们整理的是公开活动信息，**不是城市全部活动**。」
- 「经济情景是参数假设，**不是营业额预测**。」
- 「推荐用规则，缺数据标未知，**不猜**。」

## 四、现场最可能被问的三句 + 回答

| 老师可能说 | 你回答 |
|---|---|
| 「系统不错，但酒店不一定需要。」 | 「我们最想验证的不是功能有多少，而是能不能帮酒店减少信息整理时间、提前发现值得跟进的活动；您觉得哪个岗位最值得先试用？」 |
| 「能提升多少收入？」 | 「现在不能回答，也不该回答。要先把『是否被使用、节省多少时间』用试点量出来。」 |
| 「和现有收益系统什么关系？」 | 「不替代。我们做活动信息 + 来源追溯 + 简报，是收益系统的输入侧。」 |

## 五、挑 5 个问题问（按顺序）

1. 酒店现在通过哪些渠道了解周边展会、赛事和城市活动？
2. 这些信息由市场部、销售部、收益管理部还是前厅负责？
3. 有没有出现过活动信息发现太晚、错过准备的情况？
4. 更关心活动时间与位置，还是规模、客群、潜在客房需求？
5. 如果每周一份简报，哪些字段是必须的？
   （时间不够就问 1、3、5 三题）

## 六、开口要资源（一句话版本）

> 「如果企业方便，我们希望先请一位熟悉市场/销售/收益管理的老师，帮我们看一份真实城市简报；反馈积极的话，再考虑选一家酒店做小范围试点。初期不需要接入酒店系统，也不需要客户信息或敏感数据，系统运行、简报整理和问题修正由我们负责。近期不方便也完全可以，先给业务建议就很有帮助。」

## 七、老师指出问题时

> 「这个问题很重要，我们之前更多从数据角度考虑，实际业务流程确实要向企业学习。我会单独记下来，再判断是改功能还是先试点验证。」

**不要说的话：** 「我们技术上都能实现。」

## 八、出问题怎么办

| 状况 | 动作 |
|---|---|
| 网络/接口慢 | 切静态：截图 + 提前导出的 Excel。「这是昨天从系统导出的真实文件。」 |
| 某地区没数据 | 换苏州/姑苏。「太仓直接归属只有 16 条，我换数据更全的区看方法。」 |
| 地图打不开 | 停在地图清单与工作台 | 
| 问到没做的功能 | 「这个还没做，我记下来。」**不承诺** |

## 九、离场前一定拿到两样

1. **一个具体方向**：先找哪个岗位、解决哪个问题；
2. **一个下一步动作**：谁在什么时候给我们反馈（哪怕是微信上的一句话）。

## 十、回来当天要做的

把老师提的每条意见写成「问题 → 判断（改功能 / 先验证 / 不做）→ 负责人」，进 `ai-dialogue.md` 或新建 `docs/MENTOR_FEEDBACK.md`。
