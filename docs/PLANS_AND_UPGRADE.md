# 套餐与升级(客户侧,2026-10-18)

**定位**:这是给**客户**看的付费面,不是内部规划文档。它回答"我为什么花钱、花钱能多用什么"。
内部规划面板已删除;本页替代它,并已接入产品导航。

- 页面:`/plans`,导航项「套餐与升级」,对**所有访客**可见(客户要能先看到能解锁什么)。
- 两条承诺:
  1. **公开城市数据永久免费**——活动、来源链接、字段证据、数据质量在所有套餐里完整保留;
  2. **付费买的是工作流**——围绕某家酒店的筛选、区域对比、周报与变化提醒、多店管理,
     而不是把公共信息锁起来。

## 三档套餐

| 套餐 | 价格 | 面向 | 已上线能力 |
|---|---|---|---|
| 免费版 | ¥0 | 先了解这座城市 | 活动地图 / 日历 / 清单 / 场馆清单 / 知识图谱 / 数据质量与来源 |
| 专业版 | ¥980 / 酒店 / 月(试点四期免费) | 盯住一家酒店 | 酒店活动情报(单店周边筛选)、商圈洞察;周报导出与变化提醒即将上线 |
| 企业版 | ¥780 / 酒店 / 月(多店) | 管理多家酒店 | 专业版全部 + 多酒店组合对比;团队权限即将上线;私有数据与 API 后续 |

价格与试点承诺与 `PRODUCT_TIERS_AND_PERMISSIONS.md` 保持一致。企业版单价更低是因为按酒店数
打包(多店折扣),不是功能更少。

## 锁定与解锁在产品里怎么体现

1. **导航**:「酒店活动情报」「商圈洞察」始终可见;套餐不够时带 🔒 图标,提示"需要专业版"。
   可见是为了让客户知道有什么,锁只是为了说明它属于哪一档。
2. **功能页**:直接访问被锁页面时,显示说明卡(属于哪一档、为什么付费、公开数据仍免费),
   主按钮「查看套餐并解锁」跳到 `/plans`,次按钮回公开活动。
3. **升级**:`/plans` 上三张套餐卡 + 能力对照表 + 常见问题;点「演示解锁专业版/企业版」后,
   导航锁图标消失,酒店情报页解锁;专业版限**一家**酒店,企业版出现「酒店组合」多选与批量按钮。
4. **降级**:「切回免费版」立即恢复锁定,锁图标回来。

## 演示版边界(必须说清楚)

- 当前**没有账号体系与支付**,套餐状态保存在本机浏览器(localStorage,键 `menduner.plan`),
  页面上的解锁按钮明确标注「演示解锁」,并说明**未收费**。产品不会假装收到钱。
- 因此这不是权限边界:刷新/换浏览器会回到免费版;真正的开通需要下面的工程。
- **真实收费前必须补的**:
  1. 客户账号(登录、邀请、密码重置)与归属;
  2. 账号上的套餐字段(plan / 到期日 / 试用期 / 酒店数),由服务端返回;
  3. 支付或合同流程(发票/对公),以及退款与降级规则;
  4. **服务端**按 feature id 校验(现在的锁只在 UI),否则隐藏按钮不算权限;
  5. 用量记录(交付期数、导出次数)作为计费与续费依据。

## 安全与信任注意

- 付费墙**不锁公开数据**:任何套餐都能看活动、来源与证据;这既是承诺,也是差异化。
- 锁图标与升级卡是产品沟通,不是权限;在给客户演示时不要把它描述为"已收费/已开通"。
- 若以后接入支付:套餐字段必须由服务端下发并在每个付费接口校验,前端只做展示。

```bash
# 公开页面与套餐页无需登录
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1/plans     # 200(SPA)

```

浏览器:导航「套餐与升级」→ 看三档与能力对照 → 「演示解锁专业版」→「酒店活动情报」解锁
(单店);「演示解锁企业版」→ 出现「酒店组合」多选;切回免费版后两页重新上锁。

且从套餐页解锁、企业版多店对比。
