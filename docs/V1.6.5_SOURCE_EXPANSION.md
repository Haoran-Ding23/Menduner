# V1.6.5 — expanding the crawlable activity sources (Suzhou), and what cannot be crawled

**Date:** 2026-10-15 (Asia/Shanghai).
**Scope:** which public Suzhou activity sources this crawler can actually read, which were
candidates and why they were refused, and the three routes that were added to the pipeline.
**Verdict:** one new source, one new event-producing route on an existing source, and one badly
under-read route now read properly. Thirteen further candidates are crawlable pages that carry no
readable event record, and are deliberately not registered.

**Method.** Every URL below was read with `scripts/recon_event_sources.py`, which is this
repository's own read-only reconnaissance probe: TLS verification on, redirects followed by
hand with every hop recorded, `robots.txt` consulted per origin, 1 request/second per host,
no login, no cookie, no CAPTCHA solving, no proxy, no TLS relaxation, and no page body written
to disk. The project's own `User-Agent` was used. Live collection then went through the
production client (`crawler/http.py`) and the production pipeline, into throwaway databases
under `scripts/recon-scratch/`. Nothing outside this repository was modified.

### 1.1 Why a second detail route was safe to add

`festival-preview.aspx?id=` serves the identical
`div.content-outer.activity div.info-panel` block with the same 来源 / 时间 / 地点 label rows that
the calendar's `festival-detail.aspx?id=` serves, so the existing extractor reads it unchanged.
Verified live:

```
https://visitsz.wglj.suzhou.com.cn/festival-preview.aspx?id=15131
  h1      拙政园：“秋鸣” 秋季鸣虫厅堂陈设组合展
  时间：   2026-09-21 - 2026-11-18
  地点：   苏州市姑苏区东北街178号拙政园
```

Two boundaries keep this route honest:

* **The news column's own date is never an event date.** Each 最新资讯 row carries a `div.date`
  that is a *publication* date (2026-10-08 next to an exhibition running since July). The adapter
  reads only the row's link and queued preview pages, so the event date can only come from the
  preview page's own 时间. A test moves the publication date by two months and asserts the
  extracted `start_date` does not move.
* **The news column is an additional route, not the source's contract.** A portal that stops
  serving `news.aspx` sets `news_column_absent` in the attempt's investigation counters and
  changes nothing else; the calendar still decides success or failure.

### 1.2 Bounded paging, not crawling to the end

The pager grammar comes from the site's own markup and is declared per source in the registry
(`listing_pages` + `route_page_pattern`), because the largest route observed advertises
**534 pages** and this crawler is a prototype:

```yaml
listing_pages: 3
route_page_pattern: https://wglj.suzhou.gov.cn/szwhgdhlyj/{c}/list{_n}.shtml
```

`{c}` is the route's own channel segment and `{_n}` is the page number *in the form the site
prints it*: page 1 is `list.shtml` and page 2 is `list_2.shtml`, so page 1 round-trips to the
registered `crawl_url` exactly. The registry refuses a template whose derived page would leave
the registered host, transport or port, and refuses a template that cannot reproduce every
registered route. The detail budget stays a **source-wide** count: an even split would let a
second route multiply requests, so the primary activity feed keeps half the budget and the
remaining routes share the rest (12 items over three pages ⇒ `[6, 3, 3]`).

### 1.3 The new source: the city's exhibition plan, read from its own HTML

`crawler/sources/exhibition/haozhanhui.py` reads one served page per exhibition. The city plan
prints every record as a listing row whose own three fields are checkable, and the record itself
is read from that row's own page:

```
listing row   <li>2027-04-15 【能源矿产】 <a href="/exh/exh_index_cdeiog.html">CLNB2027（第十二届）新能源产业博览会</a></li>
detail page   div.exhname h1            CLNB2027（第十二届）新能源产业博览会
              div.exhinfotop            2027-04-15~04-17
              展会场馆                    苏州国际博览中心
              组织单位                    上海有色网信息科技股份有限公司
```

Four decisions are load-bearing:

* **The listing row's date is a start-day hint, and the published interval comes from the detail
  page.** The end day carries no year and belongs to the start day's year; an interval that is
  then inverted or impossible is rejected, never repaired.
* **The venue must be explicitly in Suzhou.** A record whose 展会场馆 is not a Suzhou venue is
  refused, so the city plan can never publish an out-of-town exhibition as local demand.
* **The host's own badges are not part of the name.** Two live pages carry `建议参加` and
  `好展会认证展会` inside the same `h1`; they are removed, and the page's own `<title>` — which
  prints the name inside `【】` — is used to cross-check the result.
* **The page reaches back years** (2022–2027 records in one document), so a row whose start day
  has passed is dropped rather than republished as upcoming demand.

## 4. Boundaries kept

* **HTTPS only.** No new source uses plain HTTP; `www.cnena.com` remains the single registered
  exception with its recorded integrity limitation.
* **robots first, per origin.** No candidate was requested before its `robots.txt` was read, and
  no denial was retried around.
* **No CAPTCHA, login, cookie, proxy, or verification-relaxation**, and no third-party host:
  rows that link only to `mp.weixin.qq.com` are not events this project can read, and WeChat
  stays manual-only.
* **A page that does not exist is not derived.** `list_1.shtml` 302-redirects to the homepage,
  so the template never produces it; the admitted pages are exactly those observed to answer 200
  with a different record set.
* **Publication dates never become event dates** — the rule that keeps the bureau's channels and
  the library archives out of the event tables, and the reason the news column's `div.date` is
  read but never used.
* **Raw retention and fail-closed shapes** are unchanged: pages are stored verbatim, and a
  listing whose verified container is gone raises instead of publishing from an unverified state.

## 5. How to re-run this reconnaissance

```powershell
# The probe: per-URL robots verdict, TLS, status, shell-vs-SSR, date counts, event wording
.\backend\.venv\Scripts\python.exe scripts\recon_event_sources.py `
    --input scripts\event_source_candidates.json --json-out recon.json

# Follow a listing's own links (same-host anchors, parsed, not regex-guessed)
.\backend\.venv\Scripts\python.exe scripts\recon_event_sources.py `
    --links https://wglj.suzhou.gov.cn/szwhgdhlyj/hdxx/list.shtml --links-host wglj.suzhou.gov.cn

# Prove a registered source end to end, into a throwaway database
.\backend\.venv\Scripts\python.exe -m crawler.run --source visitsz --max-items 6 --db scratch.sqlite3
```

`scripts/event_source_candidates.json` is the seed list used here, kept with the refused
candidates included so the next round starts from the evidence rather than from a guess.
