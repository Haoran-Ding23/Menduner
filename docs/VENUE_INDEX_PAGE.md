# 场馆活动清单（2026-10-15）

新增 `/venues` 页面:按场馆聚合活动。

## 为什么做这个页面

2026-10-15 的酒店访谈记录（见 `HOTEL_INTERVIEW_20261015.md`）里,受访者把问题说成:

> 官网、政府、app、太仓新闻发布提前都公布,比较容易。**官方渠道比较多,信息比较散,需要一年中的活动归纳好**

而且**全程按场所思考**:「场地」「场地大小」「音乐节在哪个场地」「活动办完后开会」。

**没有一句是按商圈说的。** 这印证了两件事:按场馆聚类是对的,而"汇总"正是他们要的东西。

地图页回答"在哪里",活动清单页回答"什么时候",**都不回答"我关心的那个剧院最近在演什么"**。这个页面回答它。

### 一个刻意的设计决定:场馆清单不受月份筛选影响

**场馆清单只看区域和类别筛选,不看年月。**

理由:一个场馆是**跨月份**排节目的。按月切会隐藏这个页面要展示的东西 —— 例如某个音乐厅排了一百场,而某个古镇只有四场。**那个数量差本身就是要看的信息。**

月份筛选**只作用于右侧选中场馆的活动列表**,因为在那里"这个月有什么"才是一个真问题。

这一条写进了页面底部的说明,因为不解释的话会被当成 bug。

### 复用了现有组件

`components/VenueEvents` **已经实现了"某场馆的全部活动"**(含"只看未来"切换、核验状态、坐标来源链接)。我没有重写,直接复用。

`utils/data.ts` 里已有 `venueHotspots`,但它和 `VenueEvents` 都**受月份筛选影响** —— 这正是需要独立页面的原因。

新增的纯函数是 `eventsByVenue()`,与 `venueHotspots` 的区别:

| | `venueHotspots` | `eventsByVenue` |
| --- | --- | --- |
| 用途 | 地图页底部的热点表 | 独立页面 |
| 无活动场馆 | 不出现 | 不出现（同样） |
| 额外返回 | `isHotspot` | `firstDate`、`hasCoordinates` |

**保留两个函数而不是合并**:一个服务于"当前筛选下的热点",一个服务于"跨月份的全量清单",语义不同。合并会让其中一个的调用方拿到不需要的概念。

## 测试

前端 **99 个测试通过**,新增 11 个覆盖 `eventsByVenue`:

| 测试 | 覆盖 |
| --- | --- |
| 按活动数降序分组 | 主行为 |
| 无活动场馆不出现 | 避免 93 行里 40 行空白 |
| 无场馆事件被忽略 | 不编造场馆 |
| 场馆 id 不在集合里被忽略 | 脏数据 |
| 主要类别取**最多**而非第一个 | 容易写错 |
| 场馆内活动按日期排序 | 排期语义 |
| 无日期活动排在**最后** | 见下 |
| `hasCoordinates` 与活动数解耦 | 地理与证据是两件事 |
| 并列时按名称稳定排序 | 渲染顺序不能变 |
| 用同一个热点阈值 | 与工作区其余部分一致 |
| 空输入返回空数组 | 不抛异常 |

## 测试写出来之后才发现的一个缺陷

`eventsByVenue` 里我写的是:

```typescript
list.sort((a, b) => (dates(a)?.[0] ?? "").localeCompare(dates(b)?.[0] ?? ""));
```

注释写着"无日期活动排最后",但 `?? ""` 让空字符串**排在最前**。

**测试立刻报错:**

```
AssertionError: expected 'none' to be 'dated'
```

改成 `?? "9999-99-99"`。**无日期活动无法排进档期,应该沉到最后,不能挡在有日期的前面。**

**这条规则是测试逼出来的,不是我先想对的。**

## 已知不足

1. **「主要类别」列反映标题关键词,不反映场馆性质。** 见上。
2. **场馆清单里的"最早活动"是所选筛选下的最早,不是场馆历史上的最早。**
3. **88 个场馆里 35 个缺坐标**,点它们时"在地图中查看"是禁用的（带说明）。
4. **不能从本页直接合并重复场馆。** 合并走 `/venues/merge` 接口或 `scripts/merge_venues.py`。
