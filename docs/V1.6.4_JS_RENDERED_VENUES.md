# V1.6.4 — the two client-rendered venue sources now publish real events

**Date:** 2026-10-15 (Asia/Shanghai). **Scope:** the two venue sources whose calendars are
rendered in the browser — 苏州国际博览中心 (`venue-suzhou-expo`) and 苏州文化艺术中心
(`venue-suzhou-arts`). **Verdict:** both were recorded as failures for the wrong reason. The
pages are not empty; they are client-rendered, and the data is served by the JSON endpoint the
host's own published JavaScript calls. Both sources now extract real dated events.

**Method.** Read-only public requests through the project's own client
(`crawler/http.py`), TLS verification always on, `robots.txt` consulted per origin before any
page or API request, no login, no CAPTCHA, no proxy pool, no credential of any kind. The
project's `User-Agent` was used unchanged. Nothing outside this repository was modified.

## 1. What the previous state said, and why it was wrong

| Source | V1.6.2 verdict (2026-10-13) | What is actually there |
| --- | --- | --- |
| 苏州文化艺术中心 `www.sscac.com.cn` | `NEEDS_DEEPER_WORK` — "client-rendered Nuxt shell with an empty state payload"; registry row `public_page_audit`, status `FAILED` | A Nuxt shell, yes — but its own bundle calls `POST /sue/api/cinema/findYanYiList`, which answers 31 upcoming performances |
| 苏州国际博览中心 `www.suzhouexpo.com` | `BLOCKED` — "0 dates anywhere; `token`/`Authorization` references present; dynamic token-header APIs are out of scope" | A Vue application whose own inline script calls `GET /api/Article/list`, which answers 51 exhibitions for 2026 |

The earlier recon was correct about the served HTML and stopped there: it never executed the
page, and it deliberately did not follow the token-bearing endpoint. That was the right
conservative call at the time, but it left two official venue calendars marked uncollectable
when the data was one public request away — and both venues are among the largest in the city.

## 2. The evidence chain, as it is read on every run

Neither endpoint is hard-coded. Both are re-discovered from material the host publishes to
every visitor, so a redeployment that moves them cannot silently produce wrong data — the
source fails closed instead.

### 苏州国际博览中心 — `crawler/sources/venue/expo.py`

1. `GET /zhanhuiricheng-389.html` (200, 17,929 bytes) — the page's own inline script declares
   `url: config.host_url + '/api/Article/list'`, `headers: {'Access-Token': config.token}` and
   `data: {cate_id: 389, is_sub: 0}`. The title must still say 苏州国际博览中心. If the
   markup stops declaring this contract, the source stops with that reason and makes no API
   request.
2. `GET /templates/expo_CN/js/config.js` (200, 127 bytes) —
   `var config = { token: 'fyxmt', host_url: ... }`. The token is **public markup shipped to
   every browser**; it is a channel identifier for this site's read-only JSON, not a user
   credential, and it is re-read from the host's own file on every run rather than stored in
   configuration or code.
3. `GET /api/Catogery/sub_list?cate_id=389&is_sub=0` (200 JSON, `success:true`, 2,435 bytes) —
   the exhibition year categories (2026 … 2017). Only the current and next year are requested;
   the past archive is never republished as live demand.
4. `GET /api/Article/list?cate_id=434&…&sort=start_time asc` (200 JSON, 44,815 bytes,
   `totalItems: 51`) — every record carries `title` and `extras.start_time`/`extras.end_time`.

`extras.start_time` carries a clock that is the CMS insertion time (`add_time` 15:57:13Z vs
`start_time` 2026-01-30T15:57:01 — same clock, edited date), so **only the calendar date is
published** — exactly the value the venue's own page renders with
`moment(start_time).format('MM月DD日')`.

### 苏州文化艺术中心 — `crawler/sources/venue/sscac.py`

1. `GET /theatre-active` (200, 376,753 bytes) — the Nuxt shell. Its `<script src>` list is the
   only thing that changes between deployments; the title must still say 苏州文化艺术中心.
2. The shell's own `/_nuxt/<hash>.js` assets are fetched in page order until one contains the
   API root `/sue/api` (today `/_nuxt/71b7f390a96335164d68.js`, 243,947 bytes). An asset that
   cannot be read — a 2.27 MB vendor bundle is past the project's 2 MB prototype cap — is
   recorded as a skip, not a failure, and is simply not the entry point.
3. `POST /sue/api/cinema/findYanYiList` with the site's own filter body
   `{"currentPage": 1, "pageSize": 100, "status": "1", "orders":[{"column":"projectStartTime","sort":"asc"}]}`
   → 200 JSON, `code:0`, 31 upcoming performances (2026-10-16 … 2027-07-10).
4. `POST /sue/api/cinema/showDramaInfoList` with the `startTime` filter its own 戏剧 page sends
   (`moment(new Date).format('YYYY-MM-DD')`) → the same upcoming programme. Without that filter
   this endpoint answers its full **2,909-record archive reaching back to 1992**, which is why
   the filter is part of the request.

Both lists describe the same programme, so the source's own record id is the identity and each
performance is published once.

## 3. Boundaries kept

* **Route allow-list per source.** `is_public_url` accepts only the two approved pages, the
  host's own `/_nuxt/*.js` assets and the two API paths (the only routes that may carry a
  query string). Anything else — another host, another path, credentials in the URL, a
  fragment — is refused before a request is built.
* **robots still decides.** Both origins were permissive before the first request
  (`www.sscac.com.cn` answers a 0-byte 200; `www.suzhouexpo.com` answers 404). A future denial
  stops the source the same way it stops a page source: `PublicAccessSource.approved_policy`
  is shared by `public_page` and `public_json`.
* **Only one header is possible.** `PublicClient.request_json` refuses any header outside
  `PUBLIC_JSON_HEADERS` (`access-token`, `content-type`, `accept`), so no adapter can attach an
  `Authorization`, `Cookie` or any other credential. A redirected non-GET request is rejected
  rather than replayed.
* **Bounded requests.** ≤ 2 pages × 100 rows per endpoint, ≤ 6 assets scanned, the 2 MB page
  cap, the project's rate spacing and retry rules, and `--max-items` still caps published
  records.
* **Nothing is invented.** A record is published only from explicit fields; it is skipped — with
  a recorded reason in the attempt's `investigation` — when it is deleted, carries no complete
  date, or has already finished. Raw responses are retained before extraction, and each event
  item's raw content is that record's own JSON object exactly as the API served it.

## 5. Tests

`crawler/tests/test_js_venue_sources.py` (21 checks) pins the contract offline through
`httpx.MockTransport`: endpoint discovery in the host's own asset, the request body and static
header taken from the host's own page/config, fail-closed behaviour when either stops
advertising them, the title-identity check, finished/deleted records skipped with a reason,
explicit-field-only extraction, the calendar-date-only rule, the credential-header refusal and
the explicit JS media allow-list. The old audit regression
(`test_expo_retains_templates_and_detects_tokens_without_calling_api`) was replaced by one that
requires the API to be called and an event to be published.

`pytest crawler/tests backend/tests` → **466 passed**.

One unrelated clock-dependent defect surfaced with the calendar roll to 2026-10-15 and is fixed
in the same change: `crawler/sources/community/douban.py::resolve_year` resolved a year-less
`10月14日` label from its bounded window alone once only one candidate year remained, which both
its own docstring and `test_no_weekday_and_no_year_is_rejected_instead_of_guessed` forbid. With
no printed weekday there is no claim to match, so the window no longer picks a year (an explicit
year elsewhere in the same interval still anchors it).

## 6. Known limits and follow-ups (not hidden)

* **苏州文化艺术中心 has no coordinates.** Its 53 events reference
  `venue-863710b26d47ccbb4d8a` (苏州文化艺术中心·金鸡湖音乐厅), whose payload has no
  coordinates, so the city's largest arts venue is still not plottable. This predates the
  change and needs a coordinate decision (the sibling 大剧院 row already carries a verified AMap
  point): `POST /venues/coordinates`, or `scripts/enrich_venue_coordinates.py` with an
  `AMAP_WEBSERVICE_KEY`.
* **One record is arguably not an event.** The arts calendar lists 苏交50元优惠券 (a discount
  coupon) with a 2027-03-31 date. It is published because the venue's own performance list
  publishes it; no keyword filter was invented to hide it, and it is a candidate for human
  review. Its event-level status is `Needs Review`, like every other event.
* **Three sources still fail, for unrelated reasons**: SIPAC (no extractable event date),
  Damai (robots disallows the search route) and Subao (no explicit leading event date). Local
  government and culture-tourism sources remain `PARTIAL` for the same date-explicitness reason.
* **Reporting artifacts.** `scripts/build_doc.py` and `scripts/build_deck.py` were updated with
  this change (source table, limitation list, metrics). The checked-in
  `docs/Menduner_技术文稿.docx`, `docs/Menduner_项目汇报.pptx` and their PDFs still describe the
  2026-10-14 state; regenerate them with those two scripts. The PDFs additionally need a
  LibreOffice step that is not installed on this machine.
