## Problems found and fixes applied

1. **Malformed compressed responses disappeared from HTTP audit totals (medium).** `httpx.DecodingError` is not a TransportError, and the request log was written only after body decoding. Added a separate decoding-error audit entry with received status and error text. The error is re-raised without treating it as a transport retry; the response is closed.
2. **Same-key records with shared raw JSON and different event locators were silently treated as duplicates (medium).** Repeated-item comparison used only raw_content. The signature now also includes extractor, locator, event/context role, original URL and mock flag. Incompatible same-key records are rejected with both raw records retained; exact repeated records still publish once and count as duplicates.
3. **Reused adapters reported cumulative counters and stale errors/warnings (medium).** Top-level client audit was job-scoped, but per-source counters and lists were not. Capture starting counters/list positions and report only current-job differences. Old diagnostics no longer turn a subsequent successful run into Partial.
4. **Individually valid observations could publish a reversed merged date interval (high).** After sources were merged and later updated, per-field selection could choose a start later than the retained end. Validate the assembled event through the existing EventRecord model before writes. Invalid publication rolls back that source's event/observation/evidence transaction, preserves the old event, and marks the new raw record Failed. Raw provenance remains durable.

Only two existing executable source files were changed: crawler/http.py and crawler/pipeline/__init__.py. Added crawler/tests/test_v15_stabilization.py (12 cases), this review, patch and validation evidence. Snapshot status documentation was updated. All original frontend files and backend implementation files remain byte-identical to the upload; the evidence architecture and schema are preserved.
