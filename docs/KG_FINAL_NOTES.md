## 一、8 轮怎么走的

| 轮次 | 议题 | 结论 |
|---|---|---|
| 1（R26） | 差距诊断：图谱该承担什么 | 核心价值是回答「为什么这场活动与我的酒店有关」并可追溯；若只能做单点查询就不该做图。定 6 条差距（P0：查询孤立、连线无证据；P0：793 POI 无关联；P0：客群依据不可见） |
| 2（R27） | 最小本体与边协议 | 7 类实体；三类边严格分离 recording（HELD_AT/REPORTED_BY/TAGGED_TO_REGION）、computed（NEARBY/WITHIN_RADIUS）、inferred（第一版禁用）；统一 GraphEdge 字段；**外键 ≠ 已核验事实** |
| 3 | 实现活动→场馆→周边设施链路 | 后端 `graph_chain.py` + `GET /graph/query/event/{id}`；真实样例还原 223m 酒店、60/105/109m POI，1682m 中心不建归属；6 项测试 |
| 4 | 工作台 → 地图断链 | 跳转带 `event=<id>`，地图页读参打开详情并同步地区/月份 |
| 5（R28） | 验收与优先级 | CONDITIONAL PASS；要求先补地图精确定位，给 3 条验收（准确定位/状态正确/异常处理） |
| 6 | 地图精确定位 | 根因：**419 条活动已核验 0 条**，`eventCoordinates` 一律返回 null；新增 `eventLocation` 区分「坐标不可用」与「关联未核验（给参考位置）」；CDP 实测坐标偏差 0.00000 |
| 7（R29） | 术语与呈现（技术 vs 酒店经理双身份） | 以经理为准：默认给人话摘要，图谱退到按钮后；9 个术语全部中文化；页面不出现 GCJ-02 / haversine-v1 |
| 8（R30） | 最终验收 | **CONDITIONAL PASS**；打分 4/5（在哪办）、3/5（离我酒店多远）、2/5（靠不靠谱）；给 3 处优先问题 |

## 二、已上线的东西（生产可验证）

1. `GET /graph/query/event/{id}?radius=800`：nodes/edges/evidenceRefs/warnings/actions；
   recorded 边不伪装已核验；computed 边带 method/坐标系/距离/半径/计算时间/输入坐标来源；
   超半径中心点只给信息不建归属；canonical_id 去重；日期冲突不静默择一。
2. `/graph` 顶部「活动关系摘要」：在哪举办 / 信息来自 / 附近有什么（酒店距活动场馆约 X 米·直线距离）/
   附近餐饮·交通（按名称判断，已注明）/ 中心点周边（超半径写明不计入归属）/ caveat 一句；
   「查看来源与依据」表格展示 29 条关系，每条可解释。
3. 地图定位：`window.__mapFocus` 可复跑核验；提示条写明「场馆关联尚未核验，地图位置仅供参考」。
4. 审核台：默认只显示 活动名字 / 活动场地 / 来源链接，三项各带 ✓ ✗ 一键过审（需审核角色）；
   值列把 `venue-xxx` 主键替换成真实名称。

验证脚本：`scripts/cdp-map-verify.mjs`（地图坐标）、`scripts/cdp-shot2.mjs`（截图）、
`backend/tests/test_graph_chain.py`（6 项）。

## 四、其他遗留（DSH 补充，均为诚实记录）

1. 图谱画布仍保留在「查看关系图」后；目标客群图层仍在（标注"规则假设"），未按早期意见移除。
2. 只实现了「活动为中心」查询；酒店为中心、商圈为中心尚未实现。
3. 活动→场馆关联核验率 0/419 是数据现状，不是显示问题。
4. places 无类型字段，`dining` / `transport` 来自后端或名称关键词，已在标题注明。
5. 无场馆坐标的活动仍无法定位，只显示原因与原始坐标。
