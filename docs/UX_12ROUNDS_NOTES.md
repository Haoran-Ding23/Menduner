# 三页渐进式披露优化：12 轮结论与遗留

- 时间：2026-10-27
- 参与：DSH（实现）+ ChatGPT（Round 32 / 33 评审）
- 最终判定：**CONDITIONAL PASS**（功能链路与交互通过阶段性验收；业务价值待真实酒店验证）

## 一、设计原则（GPT Round 32，双方认可）

> 默认只显示完成当前工作所必需的内容；用户点击「查看酒店」「查看商圈」「查看关系」之后，才展开对应信息。

酒店使用者原话式表述：
> 「我打开地图是为了找活动，不是为了研究十几种图层；我点了酒店，才需要看到酒店；我想确认信息，才进入来源和核对页面。」

## 二、12 轮完成情况

| 轮 | 页面 | 做了什么 | 实测验收 |
|---|---|---|---|
| 1 | 地图 | 默认只显示活动；酒店图层默认关；场馆热点收进「更多查看方式」 | 默认 marker 3 / 酒店 0；开图层后 66（酒店 63） |
| 2 | 图谱 | 默认只显示人话摘要；关系画布不渲染 | canvas 数量 0；点击后才出现 |
| 3 | 审核台 | 默认只突出关键三项，其余收「查看全部（共 N 个）」；修掉「有待处理但一行不显示」空表 | 三项状态摘要 + 展开/收回不丢字段 |
| 4 | 地图 | `?event=` 定位复验；找不到活动时给原因 | `__mapFocus` 命中；无坐标给说明 |
| 5 | 地图 | 「查看附近酒店」按"附近"收窄（选中活动时 3 公里内） | 63 家 → 4 家，文案区分 |
| 6 | 地图 | 「查看商圈」开关：默认关，53 个参考点，点中心才出 800 米圆与摘要 | 0 → 53 点；1 个圆 + 摘要 |
| 7 | 地图 | 三层叠加取舍、图例随层变化、加载/失败态 | 3/0/0 → 56/0/53 → 60/4/53；逐层关闭无残留 |
| 8 | 图谱 | 周边设施可展开可收起，换活动复位 | 0 → 4 → 0；画布始终 0 |
| 9 | 互通① | 地图 → 图谱摘要（带同一活动 id） | URL 带 event，摘要正确 |
| 10 | 互通② | 图谱 → 审核台（带 field，行高亮 + 滚动） | `/evidence?...&field=venueName`，1 个高亮行 |
| 11 | 互通③ | 核对字段后图谱关系状态联动（**修了真 bug**） | Needs Review → Verified，"尚未核验"警告消失 |
| 12 | 收尾 | 三页链路一次性验收；页头各加一句业务路径引导 | 三页 `.page-lead` 均可见（1133×20） |

## 三、第 11 轮修掉的真 bug（最值得记的一条）

**现象**：审核台把 `venueName` 核对通过（200）后，图谱 `HELD_AT` 边仍是 `Needs Review`。

**根因**：边状态取 `events.verification_status`（整条活动状态），而字段级核对只改 `evidence`。

**修法**：`_venue_link_status()` 让关系状态由该活动的**场馆相关字段证据**决定；
全部核验 → Verified，有未核验/冲突 → Needs Review；无字段证据时退回活动状态（不凭空变核验）。
图谱协议仍只有 Verified / Needs Review / Unknown 三种值。

## 四、GPT 终判要点（Round 33）

- 最有价值：第 1、4、5、6、9、10、11 轮（形成"发现活动 → 定位场馆 → 附近酒店/商圈 → 关系 → 核对来源"链路）
- 可合并：2+8（图谱渐进展示）、6+7（地图图层控制）、4+9（定位与跳转）
- 审核台优化属内部运营价值，不是酒店客户核心卖点
- 缺业务路径引导 → 已按它给的原话在三页各加一句
- **判定：CONDITIONAL PASS**，不阻塞阶段性汇报
- MarkerCluster 点聚合**不属于优先事项**（本轮用"商圈点降权"替代，未接插件）

## 五、遗留清单（如实）

1. 活动↔场馆关联核验率仍很低，大量活动显示"待核实"——这是数据现状，不是显示问题
2. 缺少"酒店为中心 / 商圈为中心"两条图谱查询（目前只有活动为中心）
3. 尚无真实酒店用户验证（GPT 认为这是下一阶段重点，而非继续加页面）
4. 点聚合（MarkerCluster）未接入
5. AI 审核建议试验台已上线（20 条真实建议入库），误报率刚开始统计

## 六、汇报可用结论（GPT 原话）

> 「我们已经把城市活动发现、酒店周边分析、商圈关联和来源核验连接成一条可操作、可追溯的工作流程。下一阶段希望在真实酒店场景中验证，它能否帮助工作人员更高效地发现和跟进有价值的活动。」

它同时强调：**下一阶段的重点不应该是继续增加页面，而应该是让酒店人员真正使用一次。**
