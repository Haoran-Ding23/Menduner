# 按钮有效性验收标准（GPT Round 34 + 用户要求）

> 用户原话：「要求每一个按钮都有作用和能使用（使用很重要）」
> GPT 补充：一次点击触发了请求或 DOM 更新，**不代表功能真的有用**（例：点"查看附近酒店"导致地图缩放，技术有响应、业务仍错）。

## 一、四条根因（前三项为 DSH 自查，第四项为 GPT 补充）

1. **状态来源不一致**：登录身份 vs 手填姓名；URL 参数 vs 平台内部状态。
2. **失败路径未区分**：404 / 401 / 403 / 409 都提示同一句话，用户无法判断问题出在哪。
3. **缺少效果验收**：交互写成"看起来能用"，没有证据证明它产生了效果。
4. **缺少交互契约**：没有定义"用户意图 = 实际结果"，于是误把"有响应"当成"有用"。

## 二、允许存在的控件类型与合格条件

| 类型 | 合格条件 |
|---|---|
| 导航 | 到达正确页面、对象或锚点 |
| 筛选 / 切换 | 改变对应内容，**不改变无关状态** |
| 查看 / 展开 | 展示正确详情，可关闭或恢复 |
| 修改 / 审核 | 后端成功保存，页面反馈真实状态（刷新后仍正确） |
| 导出 / 复制 | 文件确实可用，或内容确实已复制 |
| 定位 | 正确定位目标，**不产生非预期缩放** |
| 补录 / 重试 | 提供真实可执行的补救路径 |

纯展示内容不许伪装成按钮；只读角色不该看到无意义的写操作。

## 三、三档判定

| 档 | 定义 | 验收方式 |
|---|---|---|
| **A — ACTION VERIFIED** | 真正完成动作 | 点击后的可见结果 + 业务状态 + 必要时的持久化；**刷新后仍正确**，不能只看 HTTP 200 |
| **B — BLOCKED WITH REASON** | 明确说明限制 | 缺权限/数据/坐标时说明原因，并在可行时给补救路径（如"补录"）；不得谎报成功、不得产生无关副作用 |
| **C — REMOVE OR FIX** | 必须删除或修复 | 无响应、无意义、提示错误、跳错对象、动作不符合预期，以及长期不可用且无合理用途 |

**Disabled 的判定**：加载中、未选择对象、无权限这类**有明确解释**的禁用可以接受；长期无解释的禁用不合格；审核权限之外的功能原则上不展示。

## 四、最终门槛（本轮目标）

- 所有已识别控件 **100% 有明确的预期行为与权限定义**
- 所有可执行控件通过**正常路径**与适用的**失败路径**
- **确认的 NO-OP = 0**、**错误成功提示 = 0**、**错误对象操作 = 0**

## 五、我们的机器化检测口径（scripts/cdp-button-audit.mjs）

给页面注入 `MutationObserver` + `fetch/XHR` 计数，逐页枚举
`button / [role=switch] / .ant-switch / a[href] / [role=tab] / .ant-segmented-item`，
逐个点击后判定：

| 判定 | 含义 |
|---|---|
| `disabled` | 控件被禁用（需人工确认是否有解释） |
| `navigate` | URL 变化（视为有作用，但要再核对是否到"正确对象"） |
| `effect` | DOM 变化 ≥ 6 或触发网络请求或出现弹窗（视为有作用） |
| **`NO-OP`** | 以上都没有 → 必须进入 C 档处理 |

输出每页「控件数 / 禁用数 / 测得数 / 无反应数」+ 无反应清单，可存 JSON 明细，可复跑。

> 说明：NO-OP = 0 只是必要门槛；`effect` 里仍可能有"动了但不是用户想要的效果"（第 4 条根因），
> 需要按业务逐条加断言（例如点"查看附近酒店"后**视野不允许改变**）。
