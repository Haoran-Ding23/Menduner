### 关键决定：不改写 `name`

**`name` 是来源页面原文，属于证据。** 新增 `canonicalName` 记录「我们用来查询的完整名」，两者并存，并附 `canonicalNameReason` 说明依据。

这样任何人都能看出：原名是什么、我们改成了什么、为什么。

## 我试过写通用规则，但它对真实数据不成立

我先写了一条规则：

> 名字以 `中心/剧场/剧院/大厅` 结尾时，取以其为前缀的已知长名

**它对全部 5 个都返回 `None`。** 因为残缺名**不是**完整名的前缀：

```
苏州文化中心大道喜剧院   vs  苏州文化艺术中心     「艺术」在中间，不是前缀
苏州文化艺中心魔术剧场    vs  苏州文化艺术中心     来源标题本身就漏了一个字
```

**前提就是错的。** 用一个凑不出来的规则去套 5 个特例，不如写一张可复核的表 ——
所以做法与 `venue_aliases.json` 一致：显式、逐条、带依据。

**这条规则我写出来了、测了、发现不成立、然后撤掉了。** 留着它比没有更糟，因为它会让后来的人以为存在一条通用规律。

## 一个我没预料到的解法：用活动名反查

`苏州文化艺中心魔术剧场` 和`苏艺演艺...|大珍珠大厅` 都查不到，直到我看它们的**活动名**：

```
苏州文化艺术中心:互动魔术秀《开放麦吉克》
苏州文化艺术中心:「百年琴脉」吴门琴派艺术特展
```

**活动名里写的是完整的场馆名。** 而活动名是来源页面原文，用它反查没有引入任何新信息，
只是换了一个字段去找 —— 这不是猜，是同一份证据的另一个字段。

## 修了一个我自己引入的不一致

我给 `阳澄湖莲花岛` 指定了状态 `Needs Review`，但复核显示「坐标状态非 Verified: 0」。

**因为 `set_coordinates()` 把 `status` 硬编码为 `"Verified"`。** 我的意图没有生效 ——
**一个景区范围坐标被标成了「已核验」。**

**游乐场是点，景区是面。** 高德对莲花岛只提供一个代表点（在岛北侧），把它写成
`Verified` 是在声称一个这个地方并不具备的精度。

**修复：** `set_coordinates()` 新增 `status` 参数（只接受 `Verified`/`Needs Review`），
默认仍是 `Verified`，所以建筑入口的行为不变。现在：

```
坐标状态分布:  Verified 88 · Needs Review 1
Needs Review:  阳澄湖莲花岛
```

## 剩余 1 个：张家港市美术馆

**名称修正救不了它。** 我试了「张家港美术馆」和「张家港市美术馆」两个名字，高德都没有对应 POI。

它的地址记录是 `东苑路308号`，而高德在杨舍镇只有 `苏华美术馆`（长安中路）之类的候选，
**地址不一致。** 我先前差点按「杨舍镇唯一美术馆类候选」把它写进去 —— 那是从「找不到别的」
推出来的，不是从证据推出来的。地址直接否定了它。

**它是唯一一个我确认「查不到就是不写」的场馆。**
