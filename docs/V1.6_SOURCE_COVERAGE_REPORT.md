## Implementation

- Added crawler/source_registry.yaml with source_name, category, supplied url, trust_level, priority, crawl_status and stable ownership/adapter metadata. Same-host HTTPS crawl URLs retain the original supplied HTTP URLs as metadata. Status updates include reason and last_checked and touch only attempted sources.
- Added bounded official-article and Olympic detail extraction and media article selectors. Article extraction requires one explicit leading event date and explicit event year. Publication, relative and historical dates are not substituted. Olympic dates and locations come from labelled event detail fields; multi-venue tournaments have venue=null with their full location text preserved.
- Added five explicit public-page audit handlers for unsupported/protected sources. Public pages are retained as Context when accessible. Unavailable or unreliable extraction records FAILED with a reason; no fabricated events, guessed schedules or placeholder field evidence are created.
- Preserved existing raw URL/content/crawl time, normalized observations and field-level snippets/methods/confidence/raw IDs. Added job-scoped source coverage to the existing report JSON and crawler_jobs report column. SQLite schema, API routes, backend implementation and frontend files are unchanged.
- Added PyYAML==6.0.3 to the pinned backend requirements and environment reference. No other dependency version changed.
- Existing source aliases remain available; --tier1 selects exactly the ten requested websites. Max-items remains 1–5; no pagination, browser automation, login, CAPTCHA solving, mobile app crawling, token access or protected API bypass was introduced.

## Reproduce

From the repository root with the existing backend virtual environment:

```bash
python -m pip install -r backend/requirements.txt
python -m pip check
python -m pytest crawler/tests backend/tests -q
python -m crawler.run --tier1 --max-items 3 --db /absolute/path/to/isolated.sqlite3 --coverage-report docs/crawler-v16-coverage.json
python -m crawler.inspect --db /absolute/path/to/isolated.sqlite3
```

Status and counts are last-observed results; availability, page contents and event coverage may change. --tier1 includes audits and can legitimately return Partial/exit 2. A fresh database is recommended when reproducing this exact source-count comparison; repeat runs retain raw history and previous observations.
