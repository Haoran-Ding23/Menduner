# 商业规划面板(内部,2026-10-18)

**定位**:这是**内部规划工具**,不是客户页面,也不是融资材料。它把"套餐、价格、成本、试点管道、
假设验证进度、市场证据"放进一张可编辑、可保存的表,让商业决策的输入与输出放在一起看。

- 地址:`/plan`(未登录或非管理员会看到明确的 403 说明)
- 权限:**仅管理员**(`admin`)。读取和保存都走服务端角色校验——价格假设与客户名单不能出现在
  审核员或客户账号里。
- 存储:`business_plan` 表,单个 JSON 文档;保存时记录写入人(`menduner`,即你的管理员账号)。

## 面板分区

| 分区 | 内容 | 性质 |
|---|---|---|
| 顶部状态条 | 试点候选 / 已联系 / 已付费 / 盈亏平衡酒店数 / 场景年化收入 / 场景年毛利 | 由假设算出 |
| 套餐与价格 | 专业版、企业版单价(按酒店/月)、试点期数;三档能力矩阵(已有 / NEW / 暂缓) | 假设 + 已知状态 |
| 单位经济与场景 | 服务器、数据、运营人力月成本;付费酒店数、企业版占比、试点转付费率 | 假设 |
| 商业假设与验证状态 | 6 条待验证假设,每条写明验证方式、状态与当前证据 | 假设 + 进度 |
| 试点管道 | 每家候选酒店的阶段、已交付期数、联系人、下一步与日期、备注;并列出**实测**周边证据 | 人工状态 + 实测数据 |
| 里程碑 | P0–P3 的状态与备注 | 进度 |
| 市场证据(实时) | 活动总数、未来 30 天新开场/进行中、有活动场馆与酒店、字段证据、已核验/待复核、来源数、周边地点 | **实测** |

## 默认假设(可改,改完点保存)

| 项 | 默认值 | 说明 |
|---|---|---|
| 专业版 | 980 元/酒店/月 | 按酒店计费,不按坐席 |
| 企业版 | 780 元/酒店/月 | 多店折扣的占位值 |
| 试点期 | 4 期 | 四期免费,结束谈付费 |
| 月服务器 / 数据 / 运营人力 | 300 / 200 / 6000 元 | 人力为自评,可改为 0 |
| 场景付费酒店数 | 5 | 规划用,不是预测 |
| 企业版占比 | 20% | 影响混合单价 |
| 试点转付费率 | 40% | 影响"候选 × 转化 ≈ 付费" |

派生公式(面板里直接显示,不藏在代码里):

- 混合单价 = 专业版 × (1 − 企业占比) + 企业版 × 企业占比
- 月固定成本 = 服务器 + 数据 + 运营人力
- **盈亏平衡酒店数 = ⌈月固定成本 ÷ 混合单价⌉**
- 场景年化收入 = 混合单价 × 付费酒店数 × 12;年毛利 = 年化收入 − 月成本 × 12
- 预计付费 = ⌈试点候选数 × 转付费率⌉

默认值下:混合单价 940 元、月成本 6,500 元、**盈亏平衡 7 家**;5 家付费 → 年化 56,400 元、年毛利 −21,600 元。
这组数字本身就说明:**按当前假设,单靠 5 家酒店不赚钱**,要么提价/降本,要么做企业版多家打包。
面板不改这个事实,只是让它随手可算。

## 试点管道:阶段与含义

`未接触 → 已联系 → 已同意试点 → 试点中 → 试点结束 → 已付费`(另有 `已拒绝`)。

- 今天的状态:**5 家候选全部"未接触"**(没有骗自己的进度条)。
- 每个候选旁边显示**实测周边证据**:数据集中该酒店 3 km 内、未来 30 天、持续 2 天以上的
  **商务类**与**演出类**活动数,分开列,不合并成一个"热度"。
- 名单来源:洲际(样例)、濠韵楼(观前街)、长城大厦(石路)、吴宫泛太平洋(盘门)、如意(交通枢纽)。
  数据集中带"大堂/1号楼"的行是场馆级记录,谈之前先确认真实物业(面板备注里已标)。

## 保存与边界

- `GET /api/plan` / `PUT /api/plan`:**admin-only**;匿名 401、审核员 403。
- 文档上限 96 KB;保存是**整体替换**,服务端校验"非空 JSON 对象 + 大小",不逐字段建 schema
  ——规划字段变得比数据库表快,面板是唯一写入方。
- 保存记录**写入人**(来自 nginx 转发、后端校验的登录名),不只记录时间。
- 页面上的"恢复默认假设"只影响当前编辑,保存后才会覆盖服务端版本。
- 不做的:收入预测、需求强弱打分、把"活动数"当"住宿需求"。市场证据只提供**量与口径**,
  需求判断留给人工和试点反馈。

## 怎么用(每周 15 分钟)

1. 先看**商业假设与验证状态**,只改动真的有新证据的那条(例如拿到第一家试点后把 h1 从
   "待验证"改为"进行中")。
2. 更新**试点管道**:阶段、下一次动作与日期。没有进展就保持原样,不要为了"看起来在推进"改状态。
3. 看**市场证据**:活动量是否变化、来源是否健康(数据新鲜度影响周报可信度)。
4. 改**场景**里的付费酒店数/转化率,看盈亏平衡与年毛利如何变化;这些数字只用于内部决策,
   不对客户引用。

## 浏览器登录(管理员)

- 打开 `/plan` 时页面会自动请求一次 `/api/plan`。nginx 对这条路径**始终**返回 401 挑战
  (`WWW-Authenticate`),所以浏览器会弹出认证框:输入管理员账号(当前是 `menduner`)和口令即可。
- 导航里的「商业规划」只对管理员显示;未登录或审核员账号看不到,直接访问 URL 也会被拒绝。
- 如果**没有**弹出认证框(浏览器缓存过错误凭证或取消了对话框):点页面上的
  「用管理员账号登录」重试。认证成功后页面会自己打开,不需要手动刷新。
- 忘记管理员口令时重置(需要服务器 root):

```bash
sudo htpasswd -b /etc/nginx/.htpasswd menduner '<新口令>'
```

- 审核员/客户账号即使拿到 URL 也只会看到 403,并且 `/api/plan` 会拒绝其请求。

## 自检命令

```bash
curl -o /dev/null -w '%{http_code}\n' http://127.0.0.1/api/plan                    # 401(匿名)
curl -o /dev/null -w '%{http_code}\n' -u liuge:'<口令>' http://127.0.0.1/api/plan  # 403(审核员)
curl -u menduner:'<口令>' -X PUT -H 'Content-Type: application/json' \
  -d '{"document":{"pricing":{"proMonthly":980}}}' http://127.0.0.1/api/plan        # 200(管理员)
```

测试:后端 7 项(权限、空文档、整体替换、大小上限、中文往返),前端 4 项(渲染+保存、
非管理员拒绝且不请求、默认合并、派生算术)。
