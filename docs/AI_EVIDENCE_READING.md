# DeepSeek 在证据链里的位置

## 一句话

**AI 是读者,不是证据。** 它读我们**已经抓到的原始页面**,产出**建议**;任何字段的核验状态都不由它决定。

## 为什么不让 AI 自动核验

119 条活动卡在"待复核",卡点几乎全是 `venueName`(场馆名对不对)。用 AI 判定这件事等于:

> 把「聚合站的说法」换成「语言模型的说法」

两者**都不是权威来源**。AI 读完 500KB 页面后说"这场音乐会在金鸡湖音乐厅",这不是证据,是**另一个推断**。后果是:

- 页面会显示「已核验」,但**无法追溯到任何来源** → 直接违背项目的可追溯原则
- 答辩被问"这条为何已核验" → 答"AI 说的" → 这是会被扣分的答案

所以**规则不变**:只有官方来源 + 确定性提取、或人工审核,才能核验。

## 两个用途

### ① 结构化抽取(读被拒的页面)

部分政府页面被规则拒绝,原因是 `No explicit leading event date`。让 AI 读这些页面,把明确写出的字段抽出来。

**实测结论:价值有限,原因出乎意料。**

在 `government-suzhou-culture-tourism` 的 4 页上试跑,AI 成功读出字段,但抽出的活动**全是过去时的报道**:

| AI 抽出的活动名 | 页面证据原文 |
| --- | --- |
| 原创话剧《光之棱镜——百年贝聿铭》 | "**圆满首演**" |
| 画信活动颁奖仪式 | "**圆满落幕**" |
| 九月会员专属日 | "**九**月" |

这些页面本身在讲**已经发生的事**。问题不是"我们抽不出来",而是**那些页面不包含未来活动**。把它们入库会虚增活动数,且日期是过去 —— 比拒绝更糟。

所以这一项的结论是:**不做**。真正被拒的原因是内容性质,不是抽取能力。

### ② 交叉核对(核对已入库的活动)

用 AI 独立读一遍原始页面,和我们提取器的结果逐字段比对。

- **一致** → 两条独立路径得出相同结论,提高置信度(**但仍不自动核验**)
- **不一致** → 交人工确认(AI 的不可靠在这里变成了价值)
- **AI 没读到** → 记录,不视为问题

**实测:这是真正有价值的方向。**

## 实测数据

| 来源 | 页面数 | 结果 |
| --- | ---: | --- |
| `platform-shanghai-concerts` | 5 | **完全一致**:名称、日期、场馆、地址 4 字段全对 |
| `community-douban-suzhou` | 5 | 名称/场馆一致;日期 AI 抽不出(见下) |

成本约 **¥0.02 / 10 页**,耗时每页 2-5 秒。

### 两个必须说的发现

**第一:AI 在豆瓣上比我们的提取器弱。** 豆瓣只写"10月24日"不带年份,我们给 AI 的规则要求"无年份返回 null",所以它全部返回 null;而**我们的提取器用"星期几"反推出了唯一年份**。所以"提取器独有"字段不是 bug,是 AI 的保守规则使然。

**第二:原始不一致几乎全是假警报。** 首次在豆瓣跑出 3 处"不一致",逐条查证后**没有一处是提取器的错误**:

| 表现 | 实际是什么 |
| --- | --- |
| `location` 不一致 | 我们把"场馆名"和"街道地址"**拆成两个字段**,AI 把整句原文都塞进一个字段。**两者都对**,分歧在边界划分 |
| `venue` 不一致 | 我们的场馆名干净(`丝筵·丝路行歌全景沉浸式歌舞餐秀`),AI 把**整行地址当成了场馆名**。是我们更准 |
| 日期"提取器独有" | 见上,AI 的规则要求无年份返回 null |

所以 `compare()` 现在把这两类**单独归类**而不是报为发现:

- `split_differently` — 字段边界划分不同
- `only_extractor` — AI 没抽到我们抽到了

归类后重跑同一批豆瓣页面:**残留需人工 = 0**。

## 一个意外的副产品

AI 在苏州交响乐团的接口页面上**主动拒绝了回答**,而它是对的:

> 该页面并非单个具体活动页面,而是演出列表接口数据,包含 17 条独立演出,无法据此抽取单一活动

这暴露了源数据的一个性质:**一个 URL 可以承载 17 个活动**,而这个接口的 51MB 原始内容在库中被重复保存了 114 次(因为每次采集都按历史留证追加,这是 `test_v14.py` 明确断言的有意设计)。所以交叉核对**只在"一页一活动"的页面上进行**,多活动页会被跳过并标注。

## 安全

- 密钥只从 `DEEPSEEK_API_KEY` 环境变量读取,**永不打印、永不返回**
- **前端零引用**(已验证),不会进构建产物
- **数据库零出现**(已验证,全表扫描 key 前缀命中 0 次)
- 服务器上权限 600,仅服务账号可读

## 怎么用

```bash
# 交叉核对(只读,不写库)
python scripts/ai_enrich.py --limit 20 --compare

# 抽取指定来源
python scripts/ai_enrich.py --limit 10 --source government
```

`--compare` **绝不修改数据库**,是测量工具:先看输出,再决定是否把读数作为建议附到证据上。
