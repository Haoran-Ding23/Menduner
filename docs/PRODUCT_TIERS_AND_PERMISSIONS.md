## 1. 为什么酒店愿意付钱(待验证假设)

**目标客户**:苏州单体酒店的销售经理 / 市场经理 / 收益经理。

**任务**:每周安排未来一个月的档期——附近有哪些展会、演唱会、赛事?哪些和本酒店有关?可信吗?
和上周比有什么变化?

**交付**:以该酒店为中心的一份清单(日期、距离、来源链接、证据状态、变化标记)+ 一份可直接转发的周报。

**待验证目标(不是已实现效果)**:目前编辑这套信息要 2–3 小时/周,目标是压到 20 分钟。四期试点要记录:

| 指标 | 怎么记 | 用途 |
|---|---|---|
| 原来花多久 | 试点前问一次,四期后再问 | 验证"省时间"假设 |
| 收到后还花多久 | 每期回访 | 判断报告是否真的可读 |
| 是否转发/用于周会 | 每期回访 | 判断是否进入工作流 |
| 是否产生具体跟进行动 | 每期回访(如联系会务组) | 判断情报是否可行动 |
| 是否愿意付费/报价反应 | 四期结束后给真实报价 | 验证付费意愿 |

**不承诺**:收入预测。当前没有入住率、房价、间夜、预订进度,做不出来;只作为后续研究。

## 3. 统计口径(第 1 版,写入周报与 JSON)

| 项 | 定义 |
|---|---|
| 时区 | Asia/Shanghai |
| 窗口 | 周报:周一 00:00 至周日 24:00;**量统计**:`windowStart` 至 `windowEnd`(30 天 / 60 天) |
| **窗口内新开场** | `startDate` 落在窗口内 |
| **与窗口重叠** | `startDate` 早于窗口起点且 `endDate` 不早于窗口起点(已经在进行) |
| 两者关系 | 互斥;`overlapTotal = startsInside + alreadyRunning`,不重复计数 |
| 距离 | GCJ-02 坐标上的 haversine 大圆距离(km),**不是道路/步行距离** |
| 外层半径 | 10 km;阈值 3 / 5 / 10 km |
| 筛选 | 排除 demo;必须有可解析 `startDate`;场馆必须有已核验坐标(`sourceUrl`+`system`) |
| 类别 | 爬虫自动归类,**未经人工复核**;已知误判见 §6 |
| 缺失数据 | 活动人数、住宿需求、入住率、房价均无 |

**口径修正记录**:第 1 版预览把"新开场"和"已在进行"混为一个数(洲际 5 km 内 91 场)。
第 2 版拆开:**5 km 内 75 场新开场 + 16 场进行中;3 km 内 73 + 15**;全市 30 天
**142 场新开场 + 79 场进行中**。以后任何数字都必须带口径版本。

## 4. 试点周报模板(样例见 `docs/pilot/`)

**结构(1–2 页)**:

1. **本期要点**(3–4 条):本周期 3 km 内新开场多少场、其中几场值得关注;变化;
   "邻近 ≠ 住宿需求"的提醒;类别复核情况。
2. **本期值得关注**(逐条):活动/场馆/日期 + 直线距离 + **相关性:为什么值得关注(一句具体理由)**
   + **可靠性(与相关性分开)**:来源类型、事件状态、字段证据数、原始链接 + 建议动作。
   **只有 3 场就写 3 场,不凑到 8 场**;写不出具体理由的活动不进入此表。
3. **本周其余邻近活动**:仅列出,不解释——"不是不值得看,是没有足够依据写理由"。
4. **未来 30 天将开场(会展/赛事类)**:供提前安排;演出类只给数量,明细在 Excel。
5. **与本期重叠、但不是本周新开场(长期展览)**:明确排除"新增"信号。
6. **变化**:第 1 期只建基线,第 2 期起比较。
7. **数据说明**:口径、已知问题、不做的预测。

**Excel 明细列**:来源链接、类别(爬虫/人工复核)、来源类型、事件状态、字段证据数、
相关性理由、可靠性说明、建议动作、人工复核意见、**变化状态**、**客户反馈**。

**样例(洲际,W43)**:本期值得关注 3 场(紧固件展 / 纳博会 / 中国厨师节,均在博览中心,
距酒店 0.56 km、3–4 天);本周其余 20 场仅列出;未来 30 天会展类 2 条(汽车工程学会年会,
两来源未合并);长期在展 5 项单独列出。

**重跑方式**(换试点酒店/换周只需改参数,编辑判断单独放 JSON):

```bash
python scripts/build_weekly_report.py --hotel "苏州洲际酒店" --week-start 2026-10-19 \
  --today 2026-10-18 --notes docs/pilot/weekly-notes-2026-W43.json
# PDF:headless 浏览器打印生成的 HTML
msedge --headless=new --no-pdf-header-footer \
  --print-to-pdf=docs/pilot/menduner-zhouji-2026-W43.pdf docs/pilot/menduner-zhouji-2026-W43.html
```

"值得关注"的理由**不是自动生成的**:脚本只做筛选、口径与排版,理由由编辑写进 notes JSON;
没写理由的活动不会进入重点表(这正是防止报告"凑数"或臆造相关性的地方)。

## 5. 变化日志(第 2 期起)

**状态**:`首次发现` / `日期变化` / `场馆变化` / `来源明确取消` / `未再检出(待核实)`。

规则:

- **第 1 期只建基线**:所有活动记为"首次发现",不产生变化通知。
- **一次采集失败或来源列表临时删除,不直接标"取消"**;只有来源自身明确标注取消/延期才可标
  `来源明确取消`。
- 上一期存在、本期未检出的活动记为 **`未再检出(待核实)`**,需连续 N 次未检出(建议 2 次)
  且该来源采集状态正常,才升级为人工核实项;来源整体失败时整批标记"采集异常",不生成变化。
- 变化通知必须带:哪个字段、旧值、新值、来源链接、检测时间。

## 6. 数据质量:类别复核与重复来源

**类别误判(已实测,需人工复核,周报逐条标注)**:

| 活动 | 当前类别 | 人工判断 |
|---|---|---|
| 金蜘蛛苏州紧固件与技术展 | others | 工业/商务展会 |
| 纳博会 | others | 工业/商务展会 |
| 苏州奥体中心/体育中心的 5 场演唱会 | sports | 演出(疑因场馆名含"体育"被归类) |

**重复来源**:同一活动在两个来源各一条(如中国汽车工程学会年会在 cnena 与场馆官网各一条),
目前不合并;周报标注"以场馆官网为准",作为后续去重需求。

**原则**:类别与来源都影响"相关性/可靠性"判断,但二者**分开呈现**,不用一个综合分数掩盖。

## 7. 权限:三条轴(与套餐分开)

| 维度 | 决定什么 | 谁配置 | 示例 |
|---|---|---|---|
| **套餐(plan)** | 能用哪些**服务** | 商业/合同 | 专业版可导出周报 |
| **岗位(role)** | 能执行哪些**操作** | 管理员 | 查看者只读;审核员审核;管理员管账号 |
| **租户(tenant)** | 能访问哪部分**私有数据** | 合同+管理员 | A 酒店只看 A 的经营数据(本轮不启用) |

**数据三类**:公有共享(城市活动/场馆/来源/证据——匿名可读)、企业私有(**本轮不接入**)、
平台内部(审核队列/场馆合并/错误日志——仅岗位可见)。

**现状与 P0 要求**:

- 身份:**一个 nginx basic-auth 账号 = 一个登录名**;后端已校验 `X-Menduner-Login`,并新增
  **服务端角色映射**(`backend/roles.json`,可用 `MENDUNER_ROLES_PATH` 覆盖):
  `admin` / `reviewer` / `viewer`。写接口要求 `reviewer` 及以上;未配置角色的账号 **403**
  拒绝;配置缺失也 403(fail-closed)。`GET /auth/me` 返回当前身份与角色。
- **已部署并实测**:匿名写 401、reviewer 写放行、viewer 403、`/auth/me` 显示角色(临时账号验证后已删除)。
- 还没有:用户表、套餐字段、tenant(按已确认决定,**租户系统继续推迟**)。
- 客户账号只读(`viewer`);内部操作(`/review`、`/venues/merge`、`/venues/coordinates`)只对
  `reviewer`/`admin` 开放。
- **页面已拆分(P0 完成)**:
  - `/evidence` → **数据质量与来源**(公开只读):数据概览、来源与核验状态、采集来源状态、
    逐字段证据、原始来源链接、已知缺口。不需要登录,不渲染任何审核按钮。
  - `/review` → **审核台**(仅 reviewer/admin):审核/驳回/修正/撤回、全部核查、场馆维护、
    前端错误日志。导航项只对审核员显示;匿名或客户账号看到明确的 403 说明,而不是一页按钮。
  - **内部读接口同样按角色校验**:审核记录(`GET /review`、`GET /review/{id}`)、前端错误日志
    (`GET /client-errors`)、场馆维护队列(`/venues/duplicates`、`/venues/coordinates/needed`、
    `/venues/edits`)、采集明细(`GET /crawl/runs`);公开读(数据集/证据/来源健康/`/auth/me`)保持开放。
- 套餐功能**服务端判定**;隐藏按钮不算权限。
- 第二个独立账号(审核员)已创建:`liuge`(刘哥, reviewer),口令由管理员单独保管;
  新增账号时 nginx 账号 + `roles.json` 条目两边都要加,命令见 `deploy/DEPLOY.md` §11.1。

## 9. 现在不建议做的

- 收入预测/ROI 估算作为卖点(缺经营数据);
- 按"能看更多数据"分层(公开数据免费是信任基础);
- 企业私有数据接入(租户隔离未就绪前不接);
- 计费系统(试点期人工开通);
- 用一个"综合评分"合并相关性与可靠性(两者分开呈现)。
