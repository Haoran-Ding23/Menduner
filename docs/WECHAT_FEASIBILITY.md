# 微信数据获取可行性实测（2026-10-15）

针对 `github.com/bowenpay/wechat-spider` 及其依赖的「搜狗微信搜索」通道的实测记录。

## 结论

| 问题 | 答案 |
|---|---|
| **这个仓库能直接用吗** | **不能** —— Python 2.7 / Django 1.8.1(2015-2016),且其核心通道被作者标注废弃 |
| **它依赖的通道死了吗** | **没有完全死** —— 文章搜索可用,实测成功取到正文 |
| **能拿它做数据源吗** | **不可行** —— 轻度请求即触发验证码,按 IP 封锁,等待 90 秒不恢复 |

## 二、通道实测:确实还能用(部分)

### 公众号搜索 `type=1` —— 已失效

| 查询词 | 结果 |
|---|---|
| 苏州发布 | **暂无与"苏州发布"相关的官方认证订阅号** |
| 苏州文化艺术中心 | 暂无 |
| 苏州旅游 | 暂无 |
| **人民日报** | **暂无** |
| **新华社** | **暂无** |

**连人民日报和新华社都搜不到** —— 公众号检索库是空的。这与 README 说的 2019 年下线一致。

**含义:无法按公众号订阅,无法枚举某个号的推文。** 只能靠关键词搜文章。

### 文章搜索 `type=2` —— 可用

| 查询 | 结果 |
|---|---|
| 苏州 活动 | 10 条 |
| 苏州 展览 | 10 条 |
| 苏州 演出 | 10 条 |
| 苏州 音乐会 | 10 条 |

结果包含标题、公众号名、正文摘要。**实测返回的内容里有真实活动** —— 例如「苏州阅读之夜系列活动总节目单」(本项目数据库里也有这条)。

分页可用:第 1 页 10 条、第 2 页 10 条、第 3 页 7 条后耗尽。

### 正文获取 —— 技术上可行

跳转页用 JS **字符串拼接**反爬(片段分割使正则难以提取):

```javascript
url += 'https://mp.';
url += 'weixin.qq.c';
url += 'om/s?src=11';
url += '&timestamp=1792048322&ver=7027&si';
url += 'gnature=NxF...';
window.location.replace(url)
```

实测:解析 11 个拼接片段、还原地址、带 `Referer` 请求,**成功取到完整正文**(HTTP 200,正文含标题、公众号名、全文)。

## 三、致命问题:验证码封锁

**实测约 10 次请求后**(搜索 5 次 + 翻页 3 次 + 抓正文 2 次)被拦截:

```
IP：222.92.114.85   访问时间：2026.10.15 15:13:17
VerifyCode：78f0c1f9d1aa
此验证码用于确认这些请求是您的正常行为而不是自动程序发出的，需要您协助验证。
```

返回 HTML 从 **32639 字符降到 5358 字符**,文章链接数归零。

### 封锁的顽固程度

| 尝试 | 结果 |
|---|---|
| 等待 30 秒 | 未恢复 |
| 等待 60 秒 | 未恢复 |
| 等待 90 秒 | 未恢复 |
| 换 User-Agent(桌面 → iPhone) | 未恢复 |
| 换全新 HTTP 会话 | 未恢复 |
| 换移动端端点 | 未恢复 |

**按 IP 封锁,需要人工输入验证码才能解除。**

### 这意味着什么

**可抓取的数据量上限:约 10 次请求/轮,之后须人工介入。**

对本项目而言:一次采集需要几十到上百次请求。**该通道在无人值守的定时任务里不可用** —— 而本项目的采集正是 systemd timer 每天 08:00 自动跑。

## 四、必须记录的合规问题

即使技术上可行,这条通道有两个层面的问题:

### 1. 搜狗侧

`weixin.sogou.com/robots.txt` 的实测结果需单独核对,但**验证码本身就是站点表达"不接受自动化访问"的方式**。绕过验证码是明确的技术对抗。

### 2. 微信侧

本项目已有记录(见 `NEWS_PORTAL_EVALUATION.md` 与覆盖报告):腾讯曾就爬取公众号数据起诉并获法院行为保全裁定。

> 杭州铁路运输法院认为,杭州快忆违反《微信公众平台服务协议》,开发多款用于爬取微信公众平台各类数据的产品并**以此牟利**,构成不正当竞争的可能性大,需**立即停止**被诉侵权行为。

**本项目是公开仓库的课程项目、非牟利**,与判例中的"商业化爬虫产品"不同。但这条通道需要绕过验证码,性质上是技术对抗,而非公开页面的正常抓取。

## 五、如果仍需要微信内容

按合规性与可靠性排序:

| 方案 | 可行性 | 说明 |
|---|---|---|
| **人工录入 + 附公众号链接** | **推荐** | 系统已支持 `manual_only`;`social-wechat-suzhou-fabu` 现为 `MANUAL_IDENTITY_CHECK` |
| **抓政府站原版** | **推荐** | 「苏州发布」是政府号,同一内容在 `suzhou.gov.cn`,且属 `OFFICIAL_GOVERNMENT` **可自动核验** |
| 关键词搜索 + 人工核对 | 有限 | 每轮约 10 次请求即被拦,只能小批量人工辅助 |
| 自动化抓取 | **不可行** | 验证码按 IP 封锁;且即使抓到,公众号属社交平台信任等级,**只能进人工复核** |

**关键判断:即使打通这条通道,拿到的数据在本项目的核验规则下也只能是「待复核」** —— 而人工录入同样能拿到这些数据,且零风险、零封锁。
