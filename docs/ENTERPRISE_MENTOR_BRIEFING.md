# Menduner 企业导师交流材料

- 用途：周四企业导师交流（成果汇报 30% / 业务需求验证 40% / 试点合作讨论 30%）
- 依据：<https://entgroup14.com> 真实上线版本（v19，口径版本 `2026.10-caliber1-geo1-dedupe1`）
- 材料来源：框架与话术由 **ChatGPT（Round 11）** 提出，**逐页面按钮与数据由 DSH 用真实代码与生产库核实**；凡未经核实的，本文件标为「待验证」
- 原则：只讲真实功能与真实数字；**不夸大、不把待验证说成已上线、不承诺营业额提升**

---

## 0. 三个状态的定义（全场统一使用）

| 状态 | 含义 |
|---|---|
| **已上线** | 生产环境可点击、可返回结果，已写进测试 |
| **待验证** | 功能存在，但效果或业务价值未经验证（例如推荐排序是否有用、简报字段是否够） |
| **未做** | 明确没有实现，不得在汇报中暗示已有 |

**真实数字（生产库实测，2026-10-26）：** 活动 436 条、去重后 **416 个活动身份**、场馆 135 个、酒店 19 家、地区 39 个、来源 17 个、字段证据 4463 条、有坐标场馆 90 个、每日快照 3 份；**直接归属太仓市的活动 16 条**。

> 对外口径：「我们整理的是**可追溯的公开活动信息**，不是城市全部活动的覆盖量。」

## 1. 材料一：逐页面逐按钮功能讲解（**附录资料，现场不讲**）

> **现场版决定（采纳 GPT Round 12 建议）：** 周四现场只演三个核心业务动作 ——
> **① 发现活动 → ② 酒店跟进 → ③ 导出简报**。本节表格是附录资料，只在老师主动追问
> 「这一页是干什么的」时才翻出来讲，避免把业务汇报变成软件操作教学。

每页固定四问：**酒店为什么看 → 解决什么问题 → 点一下会发生什么 → 数字从哪来**。

### 1.1 本店工作台 `/workbench`

| 按钮 / 控件 | 点击后真实发生什么 | 业务意义 | 状态 |
|---|---|---|---|
| 选择酒店（下拉） | 切换当前酒店，选择记在浏览器本地 | 每家酒店只看与自己相关的活动 | 已上线 |
| 换一家酒店 | 跳到找酒店页 | 换店不迷路 | 已上线 |
| **在地图上看** | 带着当前活动/地区跳到地图 | 从"要跟进"直接到"在哪" | 已上线 |
| 周报 Excel / 周报 PDF | 下载**本店经营数据**周报（需登录） | 给店总/集团汇报 | 已上线 |
| **关注 / 待跟进 / 已跟进 / 忽略** | 写入本店租户的跟进状态（需登录） | 员工之间对同一活动有共同结论 | 已上线 |
| 采纳下拉（未知 / 已采纳 / 未采纳） | 记录"是否采纳了系统建议" | 以后能回答"推荐有没有用" | 已上线 |

**这一页回答：** 今天哪些活动值得这家酒店关注、谁在跟进、和上次比变了什么。
**数据从哪来：** 活动来自公开来源采集；距离按已核验坐标算；推荐按「业务相关性/距离/数据可信度/紧迫度」四维规则打分，**缺数据的维度显示"未知"，不作推测**。

### 1.2 城市活动地图 `/map`

| 控件 | 真实行为 | 状态 |
|---|---|---|
| 年份 / 类别下拉 | 过滤列表与地图 | 已上线 |
| 更多筛选 → 演示数据、显示已结束 | 演示数据默认**关闭**；已结束活动默认隐藏 | 已上线 |
| 月份（折叠） | 展开选月份，折叠时显示"月份：N 月"，**不改筛选状态** | 已上线 |
| 区域 chips（苏州市/太仓市/姑苏区…） | 切换统计区域 | 已上线 |
| 查看历史活动（N 条） | 把已结束活动放进当前视图 | 已上线 |
| 显示酒店（开关） | 在地图上叠加酒店点 | 已上线 |
| 活动列表 / 地图（移动端） | 列表优先，可切地图，切回不丢筛选 | 已上线 |
| 口径条「重置筛选」 | 清空时间窗口、演示、地区、类别 | 已上线 |

**这一页回答：** 城市或某个区有哪些活动、在哪里、离哪家酒店近。

### 1.3 活动清单 `/agenda`

本日 / 本周 / 本月切换；活动按「即将开始 / 进行中」分组；点击任意活动跳到地图定位。**缺坐标的活动会标注"缺坐标"，不会从统计里消失。**

**这一页回答：** 按时间顺序，这周有哪些活动；哪些今明两天就开场。

### 1.4 知识图谱 `/graph`

| 控件 | 真实行为 | 状态 |
|---|---|---|
| 用问题查图谱（场馆 / 酒店 / 商圈 + 查询） | 三个预置业务查询，结果带来源、生成方式、假设与待补充关系 | 已上线 |
| 展开商圈与酒店 / 周边餐饮交通 / 目标客群（规则） / 显示关联活动 | 控制图上显示哪些节点，客群标为**规则推断** | 已上线 |
| 在地图中查看 | 从节点跳到地图定位 | 已上线 |

页头写明**默认样例与选择依据**（按"关系完整度"选出，可复现）。
**这一页回答：** 一个活动和哪些场馆、地区、酒店有关；缺关系的会显示"待补充"。

### 1.5 找酒店 `/find-hotels`

星级柱状图（点柱子只看该星级）、地区/星级筛选、按名称或地址搜索；点任意一行进入该酒店的情报页。
**星级来自来源标注，来源未标注的显示"未标注"，不按品牌猜测。**

### 1.6 酒店活动情报 `/hotels`

选择酒店 → 看该酒店周边 10 km 内的活动与场馆；**坐标未核验的活动单独列出，不计入距离统计**。
**这一页回答：** 这家酒店附近有什么活动、有多少。

### 1.7 商圈洞察 `/insights`

| 控件 | 真实行为 | 状态 |
|---|---|---|
| **导出城市简报（Excel）** | 下载五张工作表：城市概览 / 活动明细 / 本期变化 / 来源证据 / 待确认事项（需登录） | 已上线 |
| 行政区表、商业商圈/街道表 | **分开展示**，行政区不混作商圈 | 已上线 |
| 经济贡献情景（参数输入） | 参数由用户填写；**缺参数不出金额**；结果是情景，不是观测值 | 已上线（业务价值待验证） |

**话术要提前说清：** "这是参数情景，不是营业额预测。我们不会把假设算成收入。"

### 1.8 本店经营数据 `/private`

上传本店经营数据（Excel，需登录；入住率/房价/间夜/渠道/房型）、邀请本店成员账号。**周报导出入口在工作台**（周报 Excel / 周报 PDF），不在本页。**经营数据只在本店租户内可见，不进公开页、不进导出给外部。**

### 1.9 数据质量与来源 `/evidence`

搜索活动证据、按地区/核验状态筛选、显示已核验活动；字段分「关键 / 辅助」两组；**字段已核验 ≠ 整条活动已核验**（页面上有这句解释）；内部编号与审核入口**只对审核角色可见**。

**这一页回答：** 这条数据能不能用、来源在哪、还有什么没核对。

## 2. 材料二：13 分钟演示流程

**全程只用一座城市（太仓）+ 一家真实收录酒店 + 一条真实活动 + 一份导出文件**，避免频繁切换。

| 时间 | 做什么 | 说什么（关键句） |
|---|---|---|
| 0–2 分 | 找酒店 → 选一家真实收录酒店 | "系统收录 19 家酒店，星级都来自来源标注，没标注的就显示未标注。" |
| 2–5 分 | 城市活动地图 + 活动清单 | "全市 436 条记录，去重后 416 个活动身份；太仓直接归属 16 条，我们不把它说成覆盖充分。" |
| 5–7 分 | 本店工作台：关注 → 待跟进 | "这几个状态是给员工用的，不是给系统看的；店长能看到谁在跟进。" |
| 7–9 分 | 知识图谱：用问题查图谱（选"某场馆未来有哪些活动"） | "关系有来源，缺的就写待补充，我们不补关系。" |
| 9–11 分 | 商圈洞察：参数情景 + 数据质量页 | "情景是参数算的，缺参数就不出数；数据质量页能点开每条来源。" |
| 11–13 分 | 登录 → 导出城市简报 Excel | "这份简报可以直接进周会；里面每一行都有来源。" |

**演示中必须主动说的三句边界话术：**

1. "我们整理的是公开活动信息，不是城市全部活动。"
2. "经济情景是参数假设，不是营业额预测。"
3. "推荐排序用的是规则，缺数据的维度我们标未知，不猜。"

## 3. 材料三：给企业老师的 10 个问题（现场挑 5–6 个）

顺序：**先请教实际工作 → 再谈产品价值 → 自然过渡到试点**。

| # | 问题 | 想获得什么 |
|---|---|---|
| 1 | 酒店目前通过哪些渠道了解周边展会、赛事和城市活动？ | 现有信息获取流程 |
| 2 | 这些信息一般由市场部、销售部、收益管理部还是前厅部负责？ | 使用者与决策者 |
| 3 | 有没有出现过活动信息发现太晚、错过营销或经营准备的情况？ | 真实痛点 |
| 4 | 更关心活动时间与位置，还是规模、客群和潜在客房需求？ | 功能优先级 |
| 5 | 如果每周一份城市活动简报，哪些字段是必须包含的？ | 周报业务标准 |
| 6 | 什么样的来源证据才足以让酒店采用一条活动信息？ | 可信度门槛 |
| 7 | 假设推荐了十场活动，酒店依据什么挑两三场重点跟进？ | 筛选逻辑 |
| 8 | 酒店如何评估大型活动对入住率 / ADR / RevPAR 的影响？ | 经济分析的现实基础 |
| 9 | 若做小规模试点，您建议从哪个部门、哪类酒店、哪个场景开始？ | 试点切入点 |
| 10 | 若试点有效，企业内部还要经过哪些环节才能正式采用？ | 采购/合规/预算流程 |

**开场话术：** "老师，我们能采集和整理活动，但还不确定酒店工作中最需要哪一部分。想先请教您平时怎么处理这些信息，避免我们只按技术思路继续开发。"

**被指出不足时：** "这个问题很重要，我们之前更多从数据角度考虑，实际业务流程确实要向企业学习。我们会单独记录下来，再判断是改功能还是先试点验证。"

**最可能被反驳的一句：** "系统做得不错，但酒店不一定需要。"（GPT Round 12 判断这是周四最可能失败的环节）

> **应对（建议背下来）：** "老师，我们这次最想验证的不是功能有多少，而是它能不能帮酒店减少信息整理时间、提前发现值得跟进的活动；您觉得哪个岗位最值得先试用？"

**避免的话：** "我们技术上都能实现。"

## 4. 材料四：试点资源请求（四级阶梯，先轻后重）

| 层级 | 请求什么 | 我们的承诺 |
|---|---|---|
| 第一层 | 请老师评审一份城市简报，指出哪些字段没用、哪些缺失 | 不给企业加工作量 |
| 第二层 | 20–30 分钟与相关岗位交流业务流程 | 事先给议题，不超时 |
| 第三层 | 推荐一家合适酒店，做单城市/酒店周边的范围验证 | 系统运行、简报整理、问题修正由我们负责 |
| 第四层 | 试点评价指标的定义与**公开或汇总数据** | **不要客户名单、订单明细、个人信息** |

**关键话术（可直接用）：**

> "老师，我们想请教一个后续落地的问题。系统现在能完成城市活动整理、来源追溯和简报导出，但这些功能是否真能帮酒店提高效率，还需要真实业务场景验证。如果企业这边方便，我们希望先请一位熟悉市场/销售/收益管理的老师，帮我们看一份真实的城市简报。如果反馈积极，再考虑选一家酒店做小范围试点。初期不需要接入酒店内部系统，也不需要客户信息或敏感经营数据。系统运行、简报整理、问题修正由我们负责，尽量不增加企业同事的额外工作量。如果近期不方便，也完全可以先从业务建议和材料反馈开始。"

**企业能获得什么（三项可验证，不承诺提额）：**
1. **信息价值**：能否更早发现与自身相关的活动；
2. **工作效率**：整理一份活动简报的时间是否减少；
3. **决策价值**：员工能否基于简报挑出该跟进的活动，并说清理由。

**收尾时可以只问一句：** "如果只能推荐一个最适合我们先验证的方向，您会建议找酒店的哪个岗位、解决哪一个具体问题？"

## 4.5 应急演示预案（3 分钟版，采纳 GPT Round 12 建议补齐）

**提前一天准备好三样东西：**
1. 一份**已核验的导出文件**：登录后导出太仓城市简报 Excel，存本地与 U 盘（五张表，含来源证据与待确认事项）；
2. **三张关键页面截图**：工作台（推荐 + 跟进按钮）、知识图谱（默认样例与选择依据）、数据质量（字段证据与来源链接）；
3. 一条**已确认有真实数据的演示路径**：选哪家酒店、看哪条活动、导出哪个区间，提前跑通并记下结果。

**当天出问题时的切换规则：**

| 状况 | 立即动作 | 一句话 |
|---|---|---|
| 网络打不开 / 接口慢 | 直接切静态材料（截图 + 已导出的 Excel） | "现场网络不太稳，我用提前导出的真实文件给您看，数据是昨天从系统里导出的。" |
| 某地区查不到活动 | 换到数据更全的苏州市或姑苏区 | "太仓我们直接归属只有 16 条，我换成活动更完整的区给您看方法。" |
| 地图空白 / 加载失败 | 停在活动清单与工作台 | "地图这块今天没加载出来，我们看列表和工作台，结论是一样的。" |
| 老师问到没做的功能 | 直接承认并记录 | "这个我们还没做，我先记下来，回去判断是补功能还是先在试点里验证。" |

**底线：** 任何情况下都不打开未验证的页面去"试"，也不临时承诺功能。

## 5. 材料五：后续路线图

### 短期（2–4 周）产品收尾与业务验证
- **我们做：** 关键交互测试收尾（含节点详情、移动端）、逐按钮使用说明、演示流程、数据覆盖说明、一份可评价的样例简报。
- **请企业给：** 业务反馈、岗位流程、简报字段建议。
- **交付：** 产品使用说明书 + 试点需求清单 + 可演示版本。

### 中期（1–3 个月，取决于企业意愿）小规模试点
- **我们做：** 按约定范围整理活动、生成简报、记录问题、改进数据质量与体验。
- **请企业给：** 一个试点场景、一位业务反馈联系人、必要的非敏感评价指标。
- **验证什么：** 信息准确性、活动相关性、员工使用时间、实际采纳情况。
- **交付：** 试点评估报告 + 功能优先级 + 数据质量改善方案。

### 长期（试点有效之后）商业化探索
- **我们做：** 数据维护成本、产品标准化、多酒店管理、权限隔离、商业模式。
- **请企业给：** 对采购流程、预算主体、使用场景与行业推广方式的指导。
- **交付：** 基于真实使用反馈的商业化可行性方案 —— 不预设"收费一定成立"。

**明确不做（写进汇报，避免期待错位）：** 不做需求预测、不做房价建议、不替代酒店 RMS、不承诺提升 RevPAR/ADR。
